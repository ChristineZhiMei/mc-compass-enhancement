# PRD 分析文档

## 1. PRD 核心要素

| 要素 | 内容 |
|------|------|
| 主语 | 手持已配置原版指南针的客户端玩家 |
| 宾语 | 指南针探测范围、历史目标、搜索成功反馈及搜索实现方式 |
| 动作 | 扩大范围、记录并复选历史、显示垂直方向、评估高效扫描方案 |
| 条件 | 右键配置时查看历史；左键触发扫描时记录历史；服务端找到目标时计算垂直方向 |
| 期望 | 最大 256 格、历史可复选、结果含上中下，形成可执行的性能优化建议 |

## 2. 代码入口确认

| 候选入口 | 是否为入口 | 判断依据 |
|---------|----------|---------|
| `CompassConfigComponent.MAX_RADIUS` | 是 | Codec、客户端滑块和服务端校验共享同一范围上限 |
| `MinecraftClientMixin#doAttack` 注入点 | 是 | 已配置指南针在此发送一次扫描请求，适合记录“实际搜索”历史 |
| `CompassConfigScreen` | 是 | 配置 GUI 的布局、目标回填与来源状态均在此维护 |
| `ModNetworking#handleScan` | 是 | 服务端在此获得最近目标并生成 ActionBar 成功反馈 |
| `BlockScanner` / `ContainerScanner` / `DroppedItemScanner` | 是 | 三种数据源的范围扫描及性能成本入口 |
| `CompassSearchService` / `LoadedChunkAccess` | 是 | 共享当前最佳距离、复用已加载区块并建立近到远顺序 |
| 玩家 Inventory | 否 | 设计硬约束明确禁止作为搜索来源 |

### 入口类型

前端入口与服务端入口均涉及。

### 业务逻辑范围

- 数据对象：指南针配置组件、物品 Identifier 历史、SearchResult、三个世界搜索源。
- 边界条件：历史最多 8 项且过滤已失效注册项；±2 格算“中”；只扫描当前维度已加载区块；玩家 Inventory 始终排除。

## 3. PRD 核心词含义

| 核心词 | PRD 中的含义 | PRD 上下文 |
|--------|------------|-----------|
| 历史物品 | 曾经由已配置指南针实际发起扫描的目标 Item Identifier | 配置页独立横向一行 |
| 选择 | 在配置页把某物品设为当前候选目标 | 不等于已发起搜索 |
| 搜索 | 左键发送 `ScanCompassPayload` | 此时写入客户端历史 |
| 上 / 中 / 下 | 目标相对玩家的垂直方向分段 | 成功 ActionBar 反馈 |
| 扩大范围 | 将合法半径上限提升到 256 | Codec、GUI、服务端共同生效 |

### PRD 语义相近词区分

| 词 A | 词 B | 含义区别 |
|------|------|---------|
| 选择过 | 搜索过 | 选择只改变表单状态；搜索过才进入历史 |
| 中 | 同一方块高度 | “中”允许目标与玩家 Y 坐标存在 ±2 格容差 |
| 扩大搜索范围 | 主动加载区块 | 前者只扩大已加载区块内的候选边界，后者仍被禁止 |
| 剪枝 | 近似搜索 | 剪枝只排除数学上不可能优于当前 best 的区域，不改变精确最近语义 |

## 4. 待确认项

无阻塞实现的待确认项。但 256 格同步扫描只覆盖已加载区块，且对常见方块存在服务器主线程占用风险；历史在客户端发包后记录，精确语义是“已尝试搜索”，而非服务端已完成或已找到。
